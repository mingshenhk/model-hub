LOCAL PERFORMANCE

Why memory use changes while you chat

The file you download is only one part of the memory picture. Context length and how the model is loaded matter too.

Download size is not the full runtime cost

A model package occupies storage on disk. When Ollama runs it, the model is loaded into available system memory and may be split between CPU and GPU. The active conversation also needs a context cache, so memory use can grow when you ask the model to consider more text.

Ollama documents a default context length of 4096 tokens and lets you change it with the num_ctx option. A larger context can help with a long document, but it may require more memory. Running several requests at once can raise the demand again.

Check what your computer is doing

  1. Start one model and send a short prompt.
  2. In another terminal, run ollama ps to see which model is loaded and its CPU/GPU allocation.
  3. Try a longer prompt, then check the process again and note whether the response slows down or memory becomes tight.
  4. Close the session or unload the model before comparing another one.

For example, if a model responds quickly to “Define evaporation in one sentence” but slows down when given several pages of notes, the longer context may be part of the difference. Compare on the same machine and avoid changing multiple settings at once.

Choose a useful context size

For short questions, the default may be enough. For a longer assignment, increase context only as far as the task needs, then test memory and response time. A larger context is capacity, not a guarantee that the model will understand every detail.

Ollama explains memory use, context length, parallel requests, and ollama ps in its FAQ, and documents model options such as num_ctx.
