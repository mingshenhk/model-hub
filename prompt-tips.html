BETTER INSTRUCTIONS

Give a small model a clear job

Short models often benefit from concrete instructions about the reader, output, and details to keep.

Replace a vague request with a bounded one

Vague: “Tell me about photosynthesis.”

More specific: “Explain photosynthesis to a 12-year-old in four bullet points. Mention sunlight, water, carbon dioxide, and sugar. Use simple words and finish with one question I can answer.”

The second request gives the model a reader, a length, required facts, and a clear ending. You can check each requirement against the answer.

Four details that make a prompt easier to check

  • Task: say whether you want an explanation, summary, rewrite, or quiz.
  • Audience: name the reader's age or prior knowledge.
  • Shape: request a number of bullets, a table, or a word limit.
  • Must-keep facts: list names, dates, figures, or terms that should stay unchanged.

Split a crowded request

If you ask for a summary, translation, fact check, and quiz in one message, a compact model may skip one part. Ask for the summary first, inspect it, then request the next step. This makes errors easier to spot.

When testing prompts, keep the model tag fixed and change one instruction at a time. Save the prompt that worked so you can repeat the test with another model. Ollama's Qwen3 and Gemma 4 listings show the model variants available to try.
